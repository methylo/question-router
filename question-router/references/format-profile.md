# 사용자 공통 형식 기준 (format-profile)

> 이 파일은 업무 유형이 아닙니다. 오케스트레이터가 4단계(결과 생성) 직전에 읽어, 어느 업무 유형의 결과든 같은 문체·분량·파일 형식으로 내도록 하는 기준입니다. 업무 유형별 형식(틀)은 references/formats/ 에 있고, 이 파일은 그 틀을 채울 때의 공통 규칙만 담습니다.

## 1. 문체

| 항목 | 값 | 비고 |
|---|---|---|
| 종결어미 | ~합니다 | 개조식 문서(품의·체크리스트)는 "~함"으로 통일. 한 문서 안에서 섞지 않음 |
| 호칭·시점 | 3인칭, 수신자 직함 사용 | "팀장님께"처럼 2인칭 호칭은 메일 형식에서만 |
| 문장 길이 | 한 문장 60자 이내 | 표 안 칸은 30자 이내 |
| 금지 표현 | 혁신적인·획기적인·완벽한·매우·쉽게·빠르게 / "~할 수 있습니다"로 끝나는 추상 문장 | 위반 시 결과 말미에 자가 수정 메모 1줄 |

## 2. 구성

| 항목 | 값 | 비고 |
|---|---|---|
| 결론 위치 | 맨 위 | 모든 업무 유형 공통. 배경은 결론 뒤 |
| 표 vs 산문 | 비교·목록은 표, 판단·이유는 산문 | 한 결과에 표 3개 넘으면 산문으로 전환 검토 |
| 번호·불릿 | 순서가 있으면 번호, 없으면 불릿 | 불릿 한 줄 1~2문장 |
| 빈칸 표기 | `[확인 필요]` | 값을 모르면 지어내지 않고 이 표기로 남김 |
| 근거 표기 | 주장 옆 괄호 | (파일명 p.○) / (사용자 입력) / (출처명, URL) |

## 3. 분량

| 결과 종류 | 상한 | 초과 시 |
|---|---|---|
| 대화창 결과 | A4 1쪽(약 1,500자) | 요약 1쪽 + 상세는 파일 |
| 파일 결과 | 업무 유형 형식이 정한 상한 | 상한 전에 사용자 확인 |
| 수정 결과 | 원본의 120% | 초과 전에 사용자 확인 |

## 4. 파일 형식

| 결과 종류 | 기본 | 대안 |
|---|---|---|
| 초안·중간 결과 | 대화창 텍스트 | — |
| 결재·제출 문서 | .docx | .hwpx (기관 제출 시) |
| 표·수치 | .xlsx | 대화창 표(행 20개 이하) |
| 검토 결과 | 대화창 텍스트 | .md (결함 20건 초과 시) |
| 파일명 | 한글, 날짜는 YYMMDD 접두사 | 예: 261006 예산 증액 품의.docx |

## 5. 업무 유형별 기본 형식

업무 유형 형식 파일(references/formats/)에 있는 형식 중 사용자가 평소 쓰는 것을 적습니다. 비워 두면 각 파일의 "형식 1"이 기본입니다.

| 업무 유형 | 기본 형식 | 바꾸는 조건 |
|---|---|---|
| 아이디어 기획 | (형식 1 옵션 비교 메모) | |
| 자료조사 | (형식 1 근거표) | |
| 데이터 분석 | (형식 1 분석 노트) | |
| 기획안 작성 | (형식 1 1장 품의) | |
| 결과물 검토 | (형식 1 결함 로그) | |

## 6. 적용 순서

1. 오케스트레이터는 업무 유형 노트의 5절 실행 순서를 마친 뒤, 결과를 쓰기 전에 이 파일을 읽습니다.
2. 업무 유형 형식 파일에서 형식을 고릅니다. 고르는 기준은 그 파일의 "선택 조건"이고, 5절 기본 형식이 있으면 그것을 먼저 씁니다.
3. 결과 맨 위에 `형식: ○○ — 이유 한 줄`을 씁니다. 사용자가 다른 형식을 말하면 그 형식으로 다시 냅니다.
4. 1~4절 규칙으로 문체·분량·파일 형식을 맞춥니다. 업무 유형 노트의 규칙과 충돌하면 업무 유형 노트가 우선하고, SKILL.md의 공통 규칙 세 항목과 충돌하면 공통 규칙이 우선합니다.
5. 분량 충돌 규칙: 표 형식(결함 로그·근거표·비교 매트릭스·지표 요약표)의 행 수는 업무 유형 형식이 우선합니다. 결함 20건이면 20행을 다 씁니다. 산문 부분의 분량은 이 파일 3절이 우선합니다. 표가 3절 상한을 넘기면 표는 그대로 두고 산문을 줄이며, 그래도 넘기면 4절에 따라 파일로 냅니다.
