# 기획안 작성 형식

> 업무 유형 노트: references/plan.md. 이 파일은 plan.md 6절의 결과를 담는 틀 4종입니다. 공통 문체·분량은 references/format-profile.md 를 따릅니다.

## 선택 조건

| 형식 | 쓰는 때 | 읽는 사람 | 2절 확인값과의 연결 |
|---|---|---|---|
| 1. 1장 품의 | 결정 사항이 하나이고 결재권자가 1쪽으로 판단할 때 | 결재권자 | 결정 사항이 승인·예산·인원 중 하나로 좁혀짐 |
| 2. 서술형 기획안 | 배경·방안·대안·실행을 모두 설명해야 할 때 | 결재권자 + 실행 부서 | 분량 제약이 2쪽 이상이거나 참고 양식이 서술형 |
| 3. 협업 요청 메일 | 다른 팀·외부에 참여를 요청할 때 | 상대 팀장·담당자 | 읽는 사람이 결재권자가 아니라 참여 여부를 답하는 사람 |
| 4. 실행 계획 | 결재 없이 본인이 단계별로 실행하고 중간에 판단할 때 | 실행자 본인 | 읽는 사람 = 실행자, 결정 사항 = 점검 시점의 유지·보완·전환 |

기본은 형식 1입니다. 참고 양식(2절 4항)이 있으면 그 양식의 항목 순서를 우선하고 이 형식은 칸 채우기 기준으로만 씁니다. 형식 2는 아웃라인을 먼저 내고 확인 후 본문을 씁니다.

## 형식 1. 1장 품의

용도: 결재권자가 첫 문단만 읽고 무엇을 승인하는지 알게 합니다. 개조식("~함")으로 통일합니다.

```
제목: ○○ 승인 요청
읽는 사람: ○○ / 결정 사항: ○○ 승인 여부 / 근거 자료: ○○

1. 요청 사항
   - ○○를 ○월 ○일부터 시행하고자 함. 필요 예산 [확인 필요] / 인원 ○명
2. 배경 (3줄 이내)
   - 현재 ○○ (근거: 파일명 p.○)
   - 문제 ○○ (근거: ○○)
3. 방안
   - 무엇을 / 누가 / 언제까지 — 담당 [확인 필요]
4. 대안 비교
   | | 본 안 | 현행 유지 | 대안 B |
   |---|---|---|---|
   | 비용 | | | |
   | 위험 | | | |
   | 잃는 것 | | | |
5. 예상 반론과 답
   - 반론 1: ○○ → 답: ○○ (근거: ○○)
   - 반론 2:
   - 반론 3:
6. 위험과 대응
   - ○○ 시 ○○ (발현 신호: ○○)

[확인 필요] 목록: 예산 금액, 담당자, 시행일
```

채운 예시(예시용 가상 값 — 수치는 가상입니다. 사용자 입력: 고객 문의 응대 자동화 도구 도입, 읽는 사람 사업부장, 결정 사항 예산 승인, 근거 자료 '문의 통계.xlsx', 도구 비용 월 48만 원):

```
제목: 고객 문의 1차 응대 자동화 도구 도입 승인 요청
읽는 사람: 사업부장 / 결정 사항: 도입 예산 승인 여부 / 근거 자료: 문의 통계.xlsx

1. 요청 사항
   - 1차 응대 자동화 도구를 [시행일 확인 필요]부터 3개월 시범 운영하고자 함. 필요 예산 월 48만 원 × 3개월 = 144만 원(사용자 입력), 운영 인원 1명
2. 배경
   - 월 문의 건수 1,240건, 이 중 반복 유형 5종이 61% (근거: 문의 통계.xlsx 시트1 행 2~13)
   - 1차 응답까지 평균 6.4시간 (근거: 같은 파일 시트2)
3. 방안
   - 반복 유형 상위 5종을 자동 응답으로 전환 / 담당 [확인 필요] / 3개월 시범 후 재평가
4. 대안 비교
   | | 본 안 | 현행 유지 | 대안 B: 응대 인원 1명 충원 |
   |---|---|---|---|
   | 비용 | 144만 원/3개월 | 0 | 인건비 [확인 필요] |
   | 위험 | 오응답으로 인한 불만 | 응답 지연 지속 | 채용 기간 3개월 공백 |
   | 잃는 것 | 1차 응대의 사람 접점 | 개선 기회 | 예산 유연성 |
5. 예상 반론과 답
   - 반론 1: 오응답이 불만을 키우지 않는가 → 상위 5종만 자동화하고 나머지는 사람에게 넘김 (근거: 사용자 입력)
   - 반론 2: 3개월 시범의 성공 기준은 무엇인가 → 1차 응답 시간 6.4시간 → 2시간 이하 (근거: 시트2 현재값, 목표는 사용자 입력)
   - 반론 3: 충원이 더 싸지 않은가 → 대안 B 인건비는 [확인 필요], 확인 후 4절 표 갱신
6. 위험과 대응
   - 오응답률이 [기준값 확인 필요] 초과 시 해당 유형 자동화 중단 (발현 신호: 주간 재문의율)

[확인 필요] 목록: 인건비(대안 B), 시행일, 담당자, 오응답 기준값
```

하지 않는 것: [확인 필요]를 없애려고 값을 채우지 않습니다. 승인 여부를 예측하지 않습니다.

## 형식 2. 서술형 기획안

용도: 2쪽 이상의 기획안입니다. 아웃라인을 먼저 내고 사용자 확인 후 본문을 씁니다. 종결어미는 "~합니다"로 통일합니다.

```
[문서 조건]
읽는 사람: ○○ / 결정 사항: ○○ / 근거 자료: ○○ / 형식: ○○ 양식 준용 / 분량: ○쪽

[아웃라인] (본문 전에 확인)
1. 결론·요청 — 핵심 메시지 한 줄 — 근거: 자료 ○ p.○
2. 배경·현황 — ... — 근거: ...
3. 방안 — ...
4. 대안 비교 — 현행 유지 / 대안 B — 근거: ...
5. 실행(담당·일정·예산) — [확인 필요] 항목: ...
6. 위험과 대응 — ...
예상 반론 3개: ①○○(2절에서 답) ②○○(4절에서 답) ③○○(6절에서 답)

[본문]
(아웃라인 순서대로. 수치 옆에 출처 위치. 없는 값은 [확인 필요]. 반론에 답하는 문장은 해당 절에 배치)

[자기 비평]
- 첫 문단만 읽고 결정 사항이 보이는가: 예 / 아니오(수정함)
- 출처 없는 수치: ○건 → [확인 필요]로 전환
- 대안 비교: 있음 / 없음
- 반론 3개 반영 위치: ○절·○절·○절
- [확인 필요] 목록: ○○, ○○
```

하지 않는 것: 아웃라인 확인 없이 본문을 쓰지 않습니다(사용자가 "한 번에"라고 하면 예외).

## 형식 3. 협업 요청 메일

용도: 상대가 답장 한 통으로 참여 여부를 정하게 합니다. 요청은 하나입니다.

```
제목: [요청] ○○ 관련 ○○ 협조 요청 (회신 ○월 ○일까지)

○○ 팀장님,

(첫 문단 — 요청 1개 + 상대가 얻는 것 + 소요 시간)
○○를 위해 ○○ 한 가지를 요청드립니다. 참여하시면 ○○를 얻으실 수 있고, 필요한 시간은 ○○(예: 회의 1회 30분)입니다.

(둘째 문단 — 배경 2~3문장, 근거 위치)
현재 ○○ (근거: ○○). 

(셋째 문단 — 참여하지 않을 경우와 대안)
참여가 어려우시면 ○○로 대신할 수 있습니다. 그 경우 ○○가 달라집니다.

회신: ○월 ○일까지 "참여 / 불참 / 조건부"로 답해 주시면 됩니다.

○○ 드림
```

채운 예시(사용자 입력: 개발팀에 고객 문의 유형 분류 작업 협조 요청, 소요 시간 회의 1회 30분 + 데이터 추출 1회):

```
제목: [요청] 문의 자동화 시범을 위한 문의 데이터 추출 협조 요청 (회신 10월 10일까지)

개발팀 김○○ 팀장님,

문의 1차 응대 자동화 시범을 위해 최근 3개월 문의 원문 데이터 추출 한 가지를 요청드립니다. 시범이 끝나면 개발팀 앞으로 오는 기술 문의 중 반복 유형이 자동 응답으로 걸러지고, 필요한 시간은 요건 확인 회의 1회 30분과 추출 작업 1회입니다.

현재 월 문의 [값] 건 중 반복 유형이 [값]%입니다 (근거: 문의 통계.xlsx 시트1). 자동화 대상 5종을 고르려면 원문이 필요합니다.

추출이 어려우시면 CS팀이 수기로 표본 200건을 분류하는 방법으로 대신할 수 있습니다. 그 경우 시범 시작이 2주 늦어집니다.

회신: 10월 10일까지 "참여 / 불참 / 조건부"로 답해 주시면 됩니다.

CS팀 홍○○ 드림
```

하지 않는 것: 요청을 두 개 이상 넣지 않습니다. 상대의 결정을 전제한 문장("협조해 주실 것으로 믿고")을 쓰지 않습니다.

## 형식 4. 실행 계획

용도: 결재권자 없이 본인이 실행하는 계획입니다. 목표에 이르는 경로, 단계별 할 일, 점검 시점, 전환 조건을 한 장에 둡니다. 개조식("~함")으로 통일합니다. 결재 문서가 아니므로 승인 요청과 예상 반론을 넣지 않고, 실패 대비는 3항의 전환 조건이 맡습니다.

```
제목: ○○ 실행 계획
실행자: ○○ / 목표: ○○(사용자 입력) / 기간: ○○ ~ ○○ / 제약: 예산·인원·채널(사용자 입력)

1. 목표 경로 — 목표 수치가 어디서 나오는가
   | 경로(채널·행동) | 도달 규모 | 이전 반응 | 기대 기여 |
   |---|---|---|---|
   | | [확인 필요] | [확인 필요] | |
   | 합계 | — | — | ○ / 목표 ○ |
   - 합계가 목표에 못 미치면 차이를 3항 전환 조건으로 채움
2. 단계별 실행
   | 단계(날짜) | 할 일 | 점검 시점과 확인할 값 |
   |---|---|---|
3. 점검과 전환 조건
   - 점검 1(○월 ○일): ○○가 기준 [확인 필요] 미만이면 → ○○ 추가 또는 전환
   - 점검 2(○월 ○일):
   - 첫 점검은 첫 실행 직후에 둠. 마지막 단계에만 점검을 두면 전환할 시간이 남지 않음
4. 이번 기간에 하지 않는 것
   - ○○ — 미루는 이유

[확인 필요] 목록: ○○, ○○
```

채운 예시(예시용 가상 값 — 사용자 입력: 사내 AI 활용 스터디 참여자 20명 모집, 2주, 1인 운영, 채널은 사내 메신저·게시판, 예산 없음):

```
제목: 사내 AI 활용 스터디 참여자 모집 실행 계획
실행자: 기획팀 담당자 / 목표: 참여 신청 20명(사용자 입력) / 기간: 2주 / 제약: 예산 없음·1인 운영·사내 메신저·게시판(사용자 입력)

1. 목표 경로
   | 경로 | 도달 규모 | 이전 반응 | 기대 기여 |
   |---|---|---|---|
   | 사내 메신저 전체 공지 | [확인 필요] | [확인 필요] | [확인 필요] |
   | 사내 게시판 | [확인 필요] | [확인 필요] | [확인 필요] |
   | 합계 | — | — | [확인 필요] / 목표 20명 |
2. 단계별 실행
   | 단계 | 할 일 | 점검 시점과 확인할 값 |
   |---|---|---|
   | 1주차 | 1항 표 채우기 / 메신저 공지·게시판 등록 | 공지 2일 후 신청 수 |
   | 2주차 | 마감 안내 재공지 / 신청자 명단 정리 | 마감일 신청 수 |
3. 점검과 전환 조건
   - 점검 1(공지 2일 후): 신청 수가 기준 [확인 필요] 미만이면 → 팀장 회의에서 팀별 추천 요청 추가
   - 점검 2(마감 3일 전): 목표 미달이면 → 마감 연장 여부 판단
4. 이번 기간에 하지 않는 것
   - 외부 강사 초청 — 예산 없음(사용자 입력)

[확인 필요] 목록: 채널별 도달 규모, 이전 공지 반응, 점검 1 기준값
```

하지 않는 것: 도달 규모·반응 수치를 지어내지 않습니다. 경로 표가 비어 있으면 목표 달성 여부를 판단하지 않고 비어 있다고 적습니다.
