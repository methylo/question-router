# 아이디어 기획 형식

> 업무 유형 노트: references/idea.md. 이 파일은 idea.md 6절의 결과를 담는 틀 3종입니다. 공통 문체·분량은 references/format-profile.md 를 따릅니다.

## 선택 조건

| 형식 | 쓰는 때 | 읽는 사람 | 2절 확인값과의 연결 |
|---|---|---|---|
| 1. 옵션 비교 메모 | 안을 넓힌 직후, 아직 고르지 않은 단계 | 사용자 본인·팀 | 제약이 있으면 "제약 충족" 열이 채워짐 |
| 2. 아이디어 카드 | 안 하나하나를 검증하거나 팀에 돌려 볼 때 | 안을 맡을 담당자 | 대상이 정해져 있을 때 |
| 3. 결정 메모 | 3안 이내로 압축해 상사에게 올릴 때 | 결정권자 | 목적(무엇이 좋아지면 성공인가)이 확정되어 있을 때 |

기본은 형식 1입니다. 사용자가 "정리해서 올려야 한다"고 하면 형식 3, "하나씩 더 보자"고 하면 형식 2로 바꿉니다.

형식 1에서 이미 "채택하지 않으면 잃는 것"을 적었으면, 다음 단계에서 같은 비교를 다시 하지 않습니다. 안을 고른 뒤의 기본 다음 단계는 형식 2(고른 안의 가정과 검증 방법)입니다. 형식 3은 결정권자가 따로 있을 때만 쓰고, 잃는 것 칸은 형식 1의 값을 옮겨 씁니다.

## 형식 1. 옵션 비교 메모

용도: 서로 다른 축에서 나온 안을 같은 열로 놓고 비교합니다. 안을 고르지 않습니다.

```
문제 문장(다시 쓴 것): 우리가 어떻게 하면 ~할 수 있을까
적용한 제약: 예산 / 기간 / 인원 (사용자 입력)
제외 목록: (사용자 입력 — 이미 해 본 것)

| 안 이름 | 나온 축 | 무엇을 실행하는가 | 제약 충족 | 첫 행동 | 채택하지 않으면 잃는 것 |
|---|---|---|---|---|---|
| | 축 1 ○○ 입장 | | 충족 / 일부 / 미충족 | | |
| | 축 2 SCAMPER ○○ | | | | |

겹침 확인: ○번과 ○번은 실행 내용이 같아 합쳤습니다.
전제 표시: ○○라고 가정했습니다(사용자 확인 필요).
```

채운 예시(예시용 가상 값 — 팀 워크숍, 사용자 입력: 예산 200만 원·30명·반나절·목적은 부서 간 협업, 제외: 강연·볼링):

```
문제 문장(다시 쓴 것): 우리가 어떻게 하면 다른 부서 사람과 처음으로 같이 일해 보게 할 수 있을까
적용한 제약: 200만 원 / 반나절 / 30명 (사용자 입력)
제외 목록: 강사 초청 강연, 볼링 (사용자 입력)

| 안 이름 | 나온 축 | 무엇을 실행하는가 | 제약 충족 | 첫 행동 | 채택하지 않으면 잃는 것 |
|---|---|---|---|---|---|
| 부서 교환 반나절 | 신입 입장 | 다른 부서 업무 하나를 2시간 대신 해 본다 | 충족 | 부서장 2명에게 교환 가능 업무 1개씩 받기 | 부서 간 업무 이해가 말로만 남음 |
| 과제 릴레이 | 반대 가정(모이지 않는다) | 한 부서가 시작한 과제를 다음 부서가 이어받는다 | 충족(장소 비용 0) | 하루 안에 끝나는 과제 1개 정하기 | 협업이 행사 당일로 끝남 |
| 질문 카드 점심 | 신입 입장 | 식탁마다 상대 부서에 묻고 싶었던 질문 카드를 놓는다 | 충족 | 질문 카드 30장 수집 | 평소 못 묻던 질문이 그대로 남음 |

겹침 확인: 없음.
전제 표시: "협업"을 "처음 같이 일해 보는 것"으로 좁혀 읽었습니다(사용자 확인 필요).
```

하지 않는 것: 순위를 매기거나 추천 안을 표시하지 않습니다.

## 형식 2. 아이디어 카드

용도: 안 하나를 한 장으로 적어 담당자가 검증하게 합니다. 안마다 카드 한 장입니다.

```
[카드 ○] 안 이름
나온 축: ○○
한 문장: 무엇을, 누구에게, 어떻게
가정: 이 안이 되려면 참이어야 하는 것 2개
  1. (예: 참여자가 반나절을 비울 수 있다)
  2.
대상: 누가 먼저 겪는가
첫 행동: 내일 할 수 있는 한 가지
검증 방법: 가정이 맞는지 가장 싸게 확인하는 방법
제약 충족: 충족 / 일부 / 미충족 — 미충족이면 무엇이
잃는 것: 이 안을 고르면 포기하는 것
```

채운 예시(형식 1의 "과제 릴레이"):

```
[카드 2] 과제 릴레이
나온 축: 반대 가정 — "한 장소에 모인다"를 뒤집음
한 문장: 한 부서가 오전에 시작한 과제를 다른 부서가 오후에 이어받아 하루 안에 끝낸다
가정:
  1. 두 부서가 이어서 할 수 있는 과제가 있다
  2. 인계 시점에 15분 통화가 가능하다
대상: 기획팀·개발팀 각 5명
첫 행동: 두 팀장에게 "오전에 반쯤 하다 넘길 수 있는 일"을 하나씩 묻는다
검증 방법: 과제 후보 2개를 받아 인계 지점이 있는지 본다 — 없으면 이 안은 접는다
제약 충족: 충족(장소 비용 0, 반나절 안)
잃는 것: 같은 공간에서 생기는 비공식 대화
```

하지 않는 것: 카드를 비교하거나 우열을 적지 않습니다. 비교는 형식 1에서 합니다.

## 형식 3. 결정 메모

용도: 3안 이내로 압축해 결정권자가 고르게 합니다. 결정 질문 1개로 끝납니다.

```
결정 요청: ○○ 중 하나를 ○월 ○일까지 골라 주십시오
목적(사용자 입력): 무엇이 좋아지면 성공인가
제약(사용자 입력): 예산 / 기간 / 인원

| | A안 | B안 | C안 |
|---|---|---|---|
| 무엇을 하는가 | | | |
| 제약 충족 | | | |
| 첫 행동 | | | |
| 잃는 것 | | | |
| 전제(확인 필요) | | | |

압축 과정: ○개 안에서 ○개로 줄였습니다. 제외 기준은 ○○.
결정 질문: 세 안 중 "잃는 것"을 감수할 수 있는 안은 어느 것입니까?
```

하지 않는 것: 추천 안을 쓰지 않습니다. 결정 질문까지가 결과입니다.
