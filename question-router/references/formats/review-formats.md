# 결과물 검토 형식

> 업무 유형 노트: references/review.md. 이 파일은 review.md 6절의 결과를 담는 틀 3종입니다. 공통 문체·분량은 references/format-profile.md 를 따릅니다.

## 선택 조건

| 형식 | 쓰는 때 | 읽는 사람 | 2절 확인값과의 연결 |
|---|---|---|---|
| 1. 결함 로그 | 결함의 위치·심각도·종류를 모두 찾을 때 | 작성자(수정할 사람) | 반대 독자 1명이 정해졌을 때 |
| 2. 통과 기준 체크리스트 | 통과 조건이 항목으로 정해져 있을 때 | 결재·심사 담당자 | 통과 기준(2절 2항)이 명시되었을 때 |
| 3. 독자별 반려 사유 매트릭스 | 독자를 바꿔 가며 재검토하거나 여러 독자가 볼 문서일 때 | 작성자 + 결정권자 | 결과물을 받을 사람이 2명 이상이거나, 형식 1에서 결함이 없다고 나왔을 때 |

기본은 형식 1입니다. 사용자가 통과 기준을 항목으로 주면 형식 2, "다른 관점에서도 봐 달라"고 하면 형식 3입니다. 세 형식 모두 승인·반려를 쓰지 않습니다.

## 형식 1. 결함 로그

용도: 결함마다 원문·위치·심각도·종류를 붙여 수정할 사람이 바로 찾게 합니다.

```
검토 조건: 반대 독자 ○○ / 통과 기준 ○개 / 용도 ○○ / 새 대화 여부 ○ / 원자료 ○○(없으면 "없음 — 수치 대조 생략")

[결함 목록] — 수정안 없음
| 번호 | 심각도 | 종류 | 원문 인용 | 왜 문제인가 | 위치 | 다음 행동 |
|---|---|---|---|---|---|---|
| 1 | 치명/중대/경미 | 사실 오류/근거 부족/누락 | "..." | | ○문단 ○문장 | 원자료 대조 / 자료 추가 / 항목 신설 |

치명 등급이 없는 경우 그 이유: ...
검증되지 않은 전제: ...
사실 확인 필요(자료조사로 넘김): ...
```

채운 예시는 review.md 6절에 있습니다(재택근무 확대 건의문 검토 — 예시용 가상 값). 아래 형식 2·3의 예시도 같은 건의문을 씁니다.

하지 않는 것: 수정안을 쓰지 않습니다. 총평("전반적으로")을 쓰지 않습니다.

## 형식 2. 통과 기준 체크리스트

용도: 사용자가 준 기준(또는 review.md 8절 점검 목록)을 항목별로 충족·미충족만 판정합니다. 개조식("~함")으로 통일합니다.

```
검토 조건: 반대 독자 ○○ / 통과 기준 ○개(출처: 사용자 입력 / 8절 기본) / 용도 ○○

| 번호 | 기준 | 판정 | 근거 위치(원문 인용) | 미충족 시 무엇이 있어야 충족인가 |
|---|---|---|---|---|
| 1 | | 충족 / 미충족 | "..." (○문단) | |
| 2 | | | | |

미충족 ○건 / 전체 ○건
미충족 중 결정을 좌우하는 것: ○번 — 이유
기준에 없지만 발견한 결함: ○○ (형식 1로 따로 정리 가능)
```

채운 예시(사용자 입력: 임원 보고서, 통과 기준 5개 — 수치 근거 명시·결론과 데이터 일치·위험 언급·대안 비교·용어 일관성):

```
검토 조건: 반대 독자 재무 임원 / 통과 기준 5개(사용자 입력) / 용도 분기 투자 결정

| 번호 | 기준 | 판정 | 근거 위치(원문 인용) | 미충족 시 무엇이 있어야 충족인가 |
|---|---|---|---|---|
| 1 | 수치 근거 명시 | 미충족 | "시장은 연 20% 성장한다" (2문단) — 출처 없음 | 조사 기관·연도·URL |
| 2 | 결론과 데이터 일치 | 충족 | "3분기 매출 [값]" (3문단) — 첨부 표 행 12와 일치 | — |
| 3 | 위험 언급 | 미충족 | 해당 문장 없음 | 실패 시나리오 1개 이상과 발현 신호 |
| 4 | 대안 비교 | 충족 | "현행 유지 시 ○○" (5문단) | — |
| 5 | 용어 일관성 | 미충족 | "순매출"(2문단)과 "매출"(4문단)이 같은 값을 가리킴 | 한 용어로 통일 |

미충족 3건 / 전체 5건
미충족 중 결정을 좌우하는 것: 1번 — 투자 규모의 근거가 성장률 수치 하나에 걸려 있음
기준에 없지만 발견한 결함: 4문단의 타사 사례에 출처 없음(사실 확인 필요)
```

하지 않는 것: 충족·미충족 외의 중간 판정("대체로 충족")을 쓰지 않습니다.

## 형식 3. 독자별 반려 사유 매트릭스

용도: 결재권자·실행 담당자·최종 수신자 세 입장에서 각각 반려할 이유를 찾습니다. 독자마다 별도 요청으로 받아 한 표에 모읍니다.

```
검토 조건: 독자 3종 ○○ / ○○ / ○○ / 용도 ○○

| 독자 | 반려 사유(원문 인용 + 위치) | 심각도 | 종류 | 이 독자만 보는 결함인가 |
|---|---|---|---|---|
| 결재권자 ○○ | "..." (○문단) — 이유 | | | 예 / 아니오(○○도 지적) |
| 실행 담당자 ○○ | | | | |
| 최종 수신자 ○○ | | | | |

세 독자가 모두 지적한 결함: ○○ — 우선 수정 대상
한 독자만 지적한 결함: ○○ — 그 독자가 문서를 읽는지에 따라 판단
반려 사유가 없는 독자: ○○ — 그 이유(찾지 않은 것인지, 없는 것인지)
```

채운 예시(사용자 입력: 재택근무 확대 건의문, 독자 인사위원회·부서장·일반 직원):

```
검토 조건: 독자 3종 인사위원회 / 부서장 / 일반 직원 / 용도 정책 변경 결정

| 독자 | 반려 사유(원문 인용 + 위치) | 심각도 | 종류 | 이 독자만 보는 결함인가 |
|---|---|---|---|---|
| 인사위원회 | "응답자의 82%가 찬성" (2문단) — 전체가 아니라 한 부서 값 | 치명 | 사실 오류 | 아니오(부서장도 지적) |
| 부서장 | "시행 시기는 추후 결정" (5문단) — 인력 배치 계획을 세울 수 없음 | 중대 | 누락 | 예 |
| 일반 직원 | "생산성 저하는 없을 것" (3문단) — 재택 불가 직군에 대한 언급 없음 | 중대 | 누락 | 예 |

세 독자가 모두 지적한 결함: 없음
한 독자만 지적한 결함: 시행 시기(부서장), 재택 불가 직군(일반 직원) — 둘 다 문서를 읽는 독자이므로 수정 대상
반려 사유가 없는 독자: 없음
```

하지 않는 것: 독자 셋을 한 요청에 섞어 묻지 않습니다. 독자마다 따로 받은 결과를 표로 합칩니다.
