# 데이터 분석 형식

> 업무 유형 노트: references/data.md. 이 파일은 data.md 6절의 결과를 담는 틀 3종입니다. 공통 문체·분량은 references/format-profile.md 를 따릅니다.

## 선택 조건

| 형식 | 쓰는 때 | 읽는 사람 | 2절 확인값과의 연결 |
|---|---|---|---|
| 1. 분석 노트 | 표를 처음 열어 해석할 때 | 사용자 본인 | 열 정의·비교 기준이 아직 확정되지 않았을 때도 쓸 수 있음 |
| 2. 지표 요약표 | 정해진 지표를 기간·집단별로 재계산해 검증할 때 | 지표를 관리하는 담당자 | 열 정의·단위·분모가 확정된 뒤 |
| 3. 1장 경영 보고 | 분석 결과를 결정권자에게 보고할 때 | 결정권자 | 비교 기준이 있을 때만. 없으면 형식 1로 돌아감 |

기본은 형식 1입니다. "맞는지 다시 계산해 줘"는 형식 2, "보고해야 한다"는 형식 3입니다. 비교 기준이 없는 상태에서 형식 3을 요청받으면 "비교 기준 없음 — 순위·판단 없이 사실만"을 맨 위에 적고 형식 1로 냅니다.

## 형식 1. 분석 노트

용도: 데이터 사전부터 시작해 사실·해석·가설을 층으로 나눕니다.

```
[데이터 사전]
| 열 이름 | 뜻 | 단위 | 집계 기준 | 결측 표기 | 확인 |
|---|---|---|---|---|---|
| | | | | | 확인됨 / 사용자 확인 필요 |
데이터 개요: 행 ○개, 기간 ○○~○○
비교 기준: ○○ (사용자 입력) / 없음

[사실] — 코드 실행, 근거 행 표시
-
[해석] — 사실에서 바로 따라오는 것만
-
[원인 가설 — 추정, 순위 없음]
1. ○○ (확인하려면 ○○ 데이터 필요)
2.
[표본·결측·한계] 표본 ○건, 결측 ○건(열 ○○), 일반화 한계: ○○
```

채운 예시(예시용 가상 값 — 수치는 모두 가상입니다. 사용자 입력: 월별 매출 엑셀 62행, 매출은 순매출, 비교 기준 전월):

```
[데이터 사전]
| 열 이름 | 뜻 | 단위 | 집계 기준 | 결측 표기 | 확인 |
|---|---|---|---|---|---|
| 월 | 집계 월 | YYYY-MM | 월 단위 | — | 확인됨(표 헤더) |
| 채널 | 판매 경로 | 범주(온라인/매장) | — | '기타' 3행 | 확인됨(값 2종) |
| 순매출 | 반품·세금 제외 매출 | 원 | 월 합계 | 빈칸 0행 | 확인됨(사용자 입력) |
| 주문 건수 | 결제 완료 건수 | 건 | 월 합계 | 빈칸 2행(2026-08 매장) | 확인됨 |
데이터 개요: 행 62개, 기간 2026-01~2026-09
비교 기준: 전월 (사용자 입력)

[사실] — 코드 실행, 근거 행 표시
- 9월 순매출 합계 1억 8,400만 원, 8월 2억 1,200만 원, 전월 대비 −13.2% (행 55~62)
- 감소는 온라인 채널에 집중: 온라인 −22.5%(행 55~58), 매장 +0.8%(행 59~62)
- 온라인 주문 건수는 −3.1%에 그침(행 55~58) — 건당 매출이 줄었음
[해석] — 사실에서 바로 따라오는 것만
- 전체 감소는 온라인 채널 한 곳의 건당 매출 하락으로 설명됩니다. 주문 수는 거의 유지되었으므로 고객 이탈보다 객단가 변화가 먼저 의심됩니다.
[원인 가설 — 추정, 순위 없음]
1. 9월 온라인 할인 행사로 객단가 하락 (확인하려면 프로모션 일정·할인율 데이터 필요)
2. 고가 상품군의 온라인 품절 (확인하려면 상품군별 매출 열 필요)
3. 8월 수치의 일회성 대량 주문 (확인하려면 8월 주문별 금액 분포 필요)
[표본·결측·한계] 표본 62행, 결측 2행(2026-08 매장 주문 건수), 월 단위 9개 기간이라 계절성 판단은 어려움
```

하지 않는 것: 원인을 하나로 단정하지 않습니다. 비교 기준 없이 "문제다"라고 쓰지 않습니다.

## 형식 2. 지표 요약표

용도: 지표마다 분자·분모·기간을 드러내 재계산 결과를 검증합니다.

```
열 정의(사용자 확인): ○○ = ○○ (반품·세금 포함 여부)
계산 방식: 코드 실행 / 코드 검증 안 됨

| 지표 | 분자 | 분모 | 이번 기간 | 비교 기간 | 증감 | 계산식 | 근거 행 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

분모 일치 확인: 두 기간의 분모 집계 기준 동일 / 상이(○○)
기간 일치 확인: 두 기간의 길이·시작·종료 동일 / 상이(○○)
분포: 평균 ○ / 중앙값 ○ / 최솟값 ○ / 최댓값 ○ / 이상치 ○건(행 번호)
지난 분석과 달라진 계산식: 없음 / ○○
```

채운 예시(사용자 입력: 월 전환율 재계산, 전환율 = 구매 건수 ÷ 방문자 수, 비교 기준 전월):

```
열 정의(사용자 확인): 전환율 = 구매 건수 ÷ 순방문자 수 (중복 방문 제외)
계산 방식: 코드 실행

| 지표 | 분자 | 분모 | 이번 기간 | 비교 기간 | 증감 | 계산식 | 근거 행 |
|---|---|---|---|---|---|---|---|
| 전환율(전체) | 구매 건수 | 순방문자 수 | [값] | [값] | [값]p | 구매÷순방문 | 행 2~32, 33~61 |
| 전환율(온라인) | 구매 건수(온라인) | 순방문자 수(온라인) | [값] | [값] | [값]p | 동일 | 행 2~32 채널=온라인 |

분모 일치 확인: 상이 — 비교 기간은 "총방문", 이번 기간은 "순방문"으로 집계됨(사용자 확인 필요). 같은 기준으로 재계산한 값을 아래 추가
기간 일치 확인: 동일(각 30일)
분포: 일별 전환율 평균 ○ / 중앙값 ○ / 최솟값 ○ / 최댓값 ○ / 이상치 1건(행 17, 프로모션일로 추정)
지난 분석과 달라진 계산식: 분모를 총방문에서 순방문으로 바꿈
```

값은 자리 표시입니다. 실제 결과에는 코드 실행 결과를 넣습니다.

하지 않는 것: 지표가 "좋다·나쁘다"를 쓰지 않습니다. 분모가 다르면 증감을 비교하지 않고 "비교 불가"로 둡니다.

## 형식 3. 1장 경영 보고

용도: 결론 먼저, 표 하나, 한계까지 1쪽입니다. 비교 기준이 있을 때만 씁니다.

```
제목: ○○ 분석 (기간 ○○, 비교 기준 ○○)

[결론 — 3줄 이내]
1. (사실) ○○가 비교 기준 대비 ○○ (근거 행 ○○)
2. (사실) 변화는 ○○ 집단에 집중 (근거 행 ○○)
3. (가설 — 추정) 원인 후보는 ○○·○○. 확인에 ○○ 데이터 필요

[근거 표 — 1개]
| 구분 | 이번 기간 | 비교 기간 | 증감 | 분모 |
|---|---|---|---|---|
| 전체 | | | | |
| 집단 A | | | | |
| 집단 B | | | | |
계산식: ○○ (코드 실행)

[한계]
- 표본 ○건, 결측 ○건 — ○○ 집단은 일반화 어려움
- 분모·기간 일치: 확인됨 / ○○ 상이

[다음에 확인할 것]
- 가설 ○을 확인하려면 ○○ 데이터
```

하지 않는 것: 원인을 단정하지 않습니다. 대책을 쓰지 않습니다(대책은 기획안 작성 유형).
