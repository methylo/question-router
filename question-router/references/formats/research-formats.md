# 자료조사 형식

> 업무 유형 노트: references/research.md. 이 파일은 research.md 6절의 결과를 담는 틀 3종입니다. 공통 문체·분량은 references/format-profile.md 를 따릅니다.

## 선택 조건

| 형식 | 쓰는 때 | 읽는 사람 | 2절 확인값과의 연결 |
|---|---|---|---|
| 1. 근거표 | 웹·문서에서 항목을 모아 출처별로 확인할 때 | 사용자 본인, 후속 작업자 | 용도가 "내부 참고" 또는 "보고서 인용 전 단계" |
| 2. 1장 브리핑 노트 | 조사 결과를 결정권자에게 짧게 전할 때 | 결정권자 | 용도가 "의사결정" |
| 3. 비교 매트릭스 | 대상 여러 개를 같은 기준으로 견줄 때 (제도·도구·업체·사례) | 선택을 앞둔 담당자 | 조사 대상이 2개 이상이고 기준이 정해질 때 |

기본은 형식 1입니다. 첨부 문서 요약은 형식 1에 "원문 조건" 줄을 반드시 채웁니다. 대상이 둘 이상이고 "뭐가 다른가"가 질문이면 형식 3입니다.

## 형식 1. 근거표

용도: 항목마다 출처와 확인 상태를 붙여, 찾은 것과 지어낸 것을 가릅니다.

```
조사 범위: 기간 / 지역 / 대상 / 출처 제한 (사용자 입력)

| 항목 | 내용 | 출처(문서명·위치 또는 URL, 발행 시점) | 상태 |
|---|---|---|---|
| | | | 확인됨 / 추정 / 확인 안 됨 |

원문 조건(요약 시): 표본 ○명, 기간 ○○, 지역 ○○
서로 어긋나는 출처: A는 ○○, B는 ○○ (차이의 원인 추정: ...)
반대 근거 탐색: 있음(○○) / 없음(탐색 범위 ○○)
확인 안 된 항목: ○○ — 사용자 확인 또는 추가 조사 필요
```

채운 예시(예시용 가상 값 — 회사·수치·URL은 모두 가상입니다. 사용자 입력: 경쟁사 '한빛물류'의 최근 6개월 신규 서비스, 웹 포함, 용도는 내부 참고):

```
조사 범위: 2026-04~2026-09 / 국내 / 한빛물류 신규 서비스 / 출처 제한: 공식 보도자료·언론 보도 (사용자 입력)

| 항목 | 내용 | 출처(문서명·위치 또는 URL, 발행 시점) | 상태 |
|---|---|---|---|
| 당일 배송 권역 확대 | "수도권 전역으로 당일 배송 권역을 확대한다" | 한빛물류 보도자료, hanbit-logis.example/pr/2026-05-12, 2026-05-12 | 확인됨 |
| 새벽 배송 요금 인하 | 건당 3,500원 → 2,900원 | 물류신문 기사, logis-news.example/a/4471, 2026-07-03 | 확인됨 |
| 자체 배송 앱 출시 | 앱 출시 예정이라는 언급만 있고 출시일 없음 | 같은 기사 말미 1문장 | 추정 |
| 지방 거점 2곳 신설 | 조사 범위 안에서 확인되는 자료 없음. 업계 소문 수준 | — | 확인 안 됨 |

원문 조건(요약 시): 요금 인하는 "서울·경기 한정, 9월 30일까지 시범" (기사 원문)
서로 어긋나는 출처: 보도자료는 "수도권 전역", 기사는 "서울·경기·인천 일부" — 차이의 원인 추정: 기사가 시범 단계 범위를 기준으로 씀
반대 근거 탐색: 없음(탐색 범위 네이버 뉴스 '한빛물류' 2026-04 이후 기사 23건)
확인 안 된 항목: 지방 거점 신설 — 사용자 확인 또는 추가 조사 필요
```

하지 않는 것: "확인 안 됨" 행을 지우지 않습니다. 결론을 한 문장으로 요약하지 않습니다(그것은 형식 2).

## 형식 2. 1장 브리핑 노트

용도: 결정권자가 1쪽만 읽고 판단하게 합니다. 결론 3줄이 먼저, 근거는 뒤, 미확인은 끝에 분리합니다.

```
제목: ○○에 관한 조사 (조사일 ○○, 출처 제한 ○○)

[결론 — 확인된 것만]
1. (출처)
2. (출처)
3. (출처)

[근거]
| 결론 번호 | 근거 내용 | 출처 | 발행 시점 |
|---|---|---|---|

[서로 어긋나는 자료]
- A는 ○○ / B는 ○○ — 차이의 원인 추정: ...

[확인하지 못한 것 — 결정에 영향 있음]
- ○○ (결론 ○번을 좌우함) — 확인 방법: ...

[이 노트가 다루지 않는 범위]
- 기간 ○○ 이전, 지역 ○○ 밖
```

채운 예시(사용자 입력: 사내 재택근무 제도 검토, 출처는 고용노동부·통계청 공개 자료만, 용도는 인사위원회 보고):

```
제목: 재택근무 제도 운영 현황 조사 (조사일 2026-10-06, 출처 제한: 정부·공공통계)

[결론 — 확인된 것만]
1. 재택근무 도입 사업체 비율은 [수치 — 통계청 ○○조사 ○○년] (출처: 통계청, URL)
2. 정부 지침은 재택 시 근로시간 산정 기준을 ○○로 정하고 있음 (출처: 고용노동부 ○○ 가이드, URL)
3. 도입 사업체의 주된 중단 사유는 [원문 표현 그대로] (출처: 동일 조사 ○쪽)

[근거]
| 결론 번호 | 근거 내용 | 출처 | 발행 시점 |
|---|---|---|---|
| 1 | "○○" (원문 인용) | 통계청 ○○조사 | ○○년 ○월 |
| 2 | "○○" (원문 인용) | 고용노동부 가이드 ○쪽 | ○○년 |
| 3 | "○○" (원문 인용) | 통계청 ○○조사 ○쪽 | ○○년 ○월 |

[서로 어긋나는 자료]
- 도입 비율이 통계청과 민간 조사에서 다름 — 민간 조사는 출처 제한 밖이라 결론에서 제외

[확인하지 못한 것 — 결정에 영향 있음]
- 우리 업종의 도입 비율 (결론 1을 좌우함) — 확인 방법: 조사 원자료의 업종별 표

[이 노트가 다루지 않는 범위]
- 해외 사례, 2024년 이전 자료
```

수치는 자리 표시입니다. 실제 결과에서는 열어 본 자료의 값을 그대로 넣고, 못 찾은 값은 [확인 필요]로 둡니다.

하지 않는 것: 권고안을 쓰지 않습니다. 권고는 기획안 작성 유형의 일입니다.

## 형식 3. 비교 매트릭스

용도: 대상 여러 개를 같은 기준으로 놓고, 칸마다 출처를 붙입니다.

```
비교 대상: A / B / C (사용자 입력)
비교 기준: 사용자가 준 것 ○개 + 조사 중 드러난 것 ○개(표시)

| 기준 | A | B | C |
|---|---|---|---|
| 기준 1 | 값 (출처) | 값 (출처) | 확인 안 됨 |
| 기준 2 | | | |

기준별 출처 등급: 기준 1은 공식 문서, 기준 2는 언론 보도(참고 수준)
칸이 비어 있는 이유: ○○는 공개 자료 없음 / ○○는 범위 밖
한 대상에만 있는 항목: ○○ (다른 대상은 해당 기능 없음 / 미확인 중 어느 쪽인지 표시)
```

채운 예시(사용자 입력: Claude 프로젝트·메모리·스킬 기능의 역할 비교, 출처는 support.claude.com 문서만):

```
비교 대상: 프로젝트 / 메모리 / 스킬 (사용자 입력)
비교 기준: 역할, 사용 조건, 제한 (사용자 입력)

| 기준 | 프로젝트 | 메모리 | 스킬 |
|---|---|---|---|
| 역할 | "○○" (문서 ○○) | "○○" (문서 ○○) | "○○" (문서 ○○) |
| 사용 조건 | 요금제 ○○ (문서 ○○) | 설정에서 켜야 함 (문서 ○○) | 요금제 ○○ (문서 ○○) |
| 제한 | 용량 ○○ (문서 ○○) | 확인 안 됨 | 파일 형식 ○○ (문서 ○○) |

기준별 출처 등급: 전부 공식 고객지원 문서
칸이 비어 있는 이유: 메모리의 제한은 문서에 수치가 없음
한 대상에만 있는 항목: 스킬의 "폴더 ZIP 등록" — 다른 둘은 해당 없음(미확인 아님)
```

하지 않는 것: 어느 대상이 낫다고 쓰지 않습니다. 비교까지가 결과이고 선택은 사용자가 합니다.
