## 1. 이 업무 유형으로 오는 신호 / 아닌 경우

이 업무 유형은 사용자가 이미 가진 정량 데이터(엑셀·CSV·통계표·붙여 넣은 표)를 계산·비교·추세 설명·원인 파악하는 단계입니다. "이 엑셀 봐 줘", "왜 줄었어", "어디가 문제야", "비교해 줘", "추세가 어때"가 신호입니다. 판정 기준은 두 가지입니다. 입력이 정량 데이터인가, 요청의 핵심 동작이 계산·비교·해석인가. 둘 다 해당하면 이 업무 유형입니다.

다음은 겉모습이 비슷해도 다른 업무 유형입니다.

- 자료조사: "이 시장의 최근 동향을 찾아 줘"처럼 밖에서 정보를 모으는 요청입니다. 입력이 표가 아니라 주제나 질문이면 자료조사입니다.
- 결과물 검토: "이 보고서의 표 설명이 자연스러운지 봐 줘"처럼 이미 쓰인 결과물의 표현·구성을 점검하는 요청입니다. 계산이나 해석이 목적이 아니면 결과물 검토입니다.

## 2. 먼저 확인하는 것

| 확인 항목 | 왜 필요한가 | 없을 때 생기는 일 |
|---|---|---|
| 열의 정의(매출이 총매출인지 순매출인지, 반품·세금 포함 여부) | 정의가 다르면 계산이 맞아도 답이 틀립니다[3] | AI가 열 이름만 보고 의미를 가정합니다 |
| 단위와 기간(원/천원, 월/누적, 시작·종료 시점) | 단위·기간이 다른 값을 같은 선상에서 비교하는 오류를 막습니다 | 기간 길이가 다른 두 값이 그대로 비교됩니다 |
| 비교 기준(전월·전년 동월·목표·타 부서) | 기준이 없으면 "줄었다"는 판단 자체가 성립하지 않습니다 | AI가 임의의 기준을 잡습니다 |
| 분모(비율일 때 전체 대상의 집계 기준) | 분모가 다른 비율은 비교할 수 없습니다[8] | 전환율·비율 비교가 잘못된 결론으로 이어집니다 |

## 3. 숫자 해석을 그대로 믿으면 안 되는 이유

표를 넘기고 "무엇이 문제인지 설명해 줘"라고 하면 두 층의 오류가 생길 수 있습니다.

첫째, 읽기 오류입니다. 모델이 표를 부주의하게 읽어 행을 누락하거나 잘못된 셀을 인용하는 오류(data referencing error)가 확인되었고, 이 오류는 자기 반성이나 추가 프롬프팅으로는 잘 걸러지지 않으며 별도의 검증 절차(사전 확인, 근거 인용 요구, 복수 응답 대조)가 있어야 줄어듭니다[3].

둘째, 계산 오류입니다. 숫자는 토큰화 방식에 따라 표기가 갈리고, 모델의 내부 표현은 정확한 값이 아니라 통계적 맥락을 반영하기 때문에 자연어로 시킨 합계·평균·증감률은 틀릴 위험이 있습니다. 코드를 생성해 실제로 실행하는 방식이 모델이 직접 단계별로 계산하는 방식보다 정확하다고 보고됩니다[10]. Anthropic의 코드 실행 도구도 pandas 같은 라이브러리로 통계량을 계산하도록 설계되어 있습니다[1][2].

두 층을 모두 통과해도 해석의 함정이 남습니다. 전체 합계에서는 보이던 추세가 하위 집단으로 나누면 뒤집히는 심슨의 역설[4], 분모를 보지 않고 분자만 비교하는 분모 무시[8], 평균에 가려진 분포[7], 작은 표본을 전체로 일반화하는 오류[9], 함께 움직인 두 지표를 원인과 결과로 단정하는 상관·인과 혼동[5]입니다. 이 함정들은 계산이 정확해도 생깁니다. 그래서 숫자를 읽게 하기 전에 "무엇을 세었는가"부터 묻습니다.

## 4. 질문 전략

### 4-1. 계산은 코드 실행에 위임

무엇을: 합계·평균·증감률 같은 계산을 암산하듯 답하게 하지 않고, 코드를 실행해 계산하고 과정을 보여 주게 합니다.
왜: 자연어 계산은 오류 위험이 있고, 코드 실행 방식이 더 정확합니다[2][10]. 계산 과정을 보이게 하면 어느 단계에서 틀렸는지 사용자가 찾습니다[6].
질문 문장:
```
이 계산은 코드를 실행해서 정확한 숫자로 보여주고, 계산 과정도 같이 표시해줘.
```

### 4-2. 열 정의·단위·기간부터 확인

무엇을: 분석 전에 각 열이 무엇을 세는지, 단위와 기간이 무엇인지 먼저 정리하게 합니다.
왜: 표를 잘못 인용하는 오류는 모델 스스로 알아채기 어렵고, 사전 확인 절차가 검증 단계로 작동합니다[3].
질문 문장:
```
분석 전에 이 표에서 각 열이 정확히 무엇을 의미하는지, 매출액이 세금이나 반품을 포함하는지부터 정리해서 알려줘.
```

### 4-3. 근거 행 인용 요구

무엇을: 결론을 내리기 전에 근거가 된 행이나 값을 표에서 그대로 인용하게 합니다.
왜: 관련 부분을 먼저 인용하게 하면 근거 없는 진술이 줄고, 인용을 찾지 못한 주장은 제거할 수 있습니다[11][12].
질문 문장:
```
결론을 내리기 전에, 그 근거가 된 행 데이터를 표에서 그대로 인용해서 보여줘.
```

### 4-4. 상관과 인과 구분

무엇을: 두 지표가 함께 움직였을 때 원인이라고 단정하기 전에 다른 요인(계절·프로모션·신제품)이 있는지 확인하게 합니다.
왜: 교란변수가 두 지표를 동시에 움직였을 때도 상관은 나타납니다[5].
질문 문장:
```
마케팅비와 매출이 같이 올랐는데, 계절이나 신제품 출시 같은 다른 요인 때문일 가능성도 확인해줘.
```

### 4-5. 하위 집단으로 재계산

무엇을: 전체 합계·평균만 보지 않고 지역·제품·부서로 나눠 같은 결론이 나오는지 다시 계산하게 합니다.
왜: 하위 집단에서 일관된 추세가 전체로 합치면 뒤집히거나 사라질 수 있습니다[4].
질문 문장:
```
전체 합계 말고 지역별, 제품별로 나눠서 계산해도 같은 결론이 나오는지 확인해줘.
```

### 4-6. 평균 대신 분포 요청

무엇을: 평균만 묻지 않고 중앙값·최댓값·최솟값·이상치 여부를 함께 요청합니다.
왜: 평균은 이상치와 편차를 가려 대다수의 실제 상황을 숨깁니다[7].
질문 문장:
```
평균만 말고 중앙값이랑 최댓값, 최솟값도 같이 보여주고 이상치가 있는지 확인해줘.
```

### 4-7. 비율 비교 시 분모 명시

무엇을: 퍼센트·비율을 비교할 때 두 수치의 분모가 같은 기준으로 집계되었는지 먼저 확인하게 합니다.
왜: 분자에만 주목하고 분모를 간과하면 서로 다른 모집단의 비율을 그대로 비교하게 됩니다[8].
질문 문장:
```
이번 달 전환율과 지난달 전환율을 비교할 때, 분모가 되는 방문자 수 집계 기준이 같은지 확인해줘.
```

### 4-8. 결론 전에 반례와 표본 수 확인

무엇을: 답을 받은 뒤 그 결론과 맞지 않는 데이터가 있는지 다시 찾게 하고, 표본 수를 확인시킵니다.
왜: 작은 표본의 패턴을 전체로 일반화하는 오류가 흔하고[9], 복수 응답을 대조하는 검증 절차가 정확도를 높입니다[3].
질문 문장:
```
이 결론과 다른 패턴을 보이는 데이터가 있는지 다시 찾아보고, 표본 수가 몇 개인지도 알려줘.
```

### 4-9. 데이터 사전 먼저 요청

무엇을: 계산을 시키기 전에 열마다 이름·의미·단위·집계 기준·결측 표기를 적은 표(데이터 사전)를 먼저 만들게 하고, 모르는 칸은 비워 두게 합니다.
왜: 4-2의 확인을 표 한 장으로 고정하는 방법입니다. 사전이 있어야 이후 계산·해석이 어느 정의 위에서 이뤄졌는지 남고, 모델이 열 이름만 보고 의미를 가정하는 오류[3]를 사용자가 칸 단위로 잡습니다.
질문 문장:
```
계산하기 전에 열마다 이름, 뜻, 단위, 집계 기준(월/누적), 결측 표기를 표로 먼저 정리해줘. 표만 보고 알 수 없는 칸은 비워 두고 나한테 물어봐.
```

### 4-10. 사실·해석·원인 가설 분리

무엇을: 답을 "표에서 읽히는 사실", "그 사실에 대한 해석", "원인 가설"로 나눠 쓰게 하고, 비교 기준이 없으면 순위나 우선순위를 매기지 않게 합니다.
왜: 세 층이 한 문장에 섞이면 "줄었다"(사실)와 "문제다"(해석)와 "경쟁사 때문이다"(가설)가 같은 무게로 읽힙니다. 상관을 인과로 단정하는 오류[5]는 대부분 이 섞임에서 생깁니다. 비교 기준이 없는 상태의 순위는 모델이 임의 기준으로 매긴 것입니다.
질문 문장:
```
답을 세 칸으로 나눠줘. 표에서 바로 읽히는 사실, 그 사실에 대한 해석, 원인 가설. 가설에는 '가설'이라고 붙이고, 내가 비교 기준을 주기 전에는 어느 것이 더 중요한지 순위를 매기지 마.
```

## 5. 실행 순서

1. 표를 열고 데이터 사전(열 이름·뜻·단위·집계 기준·결측 표기)과 행 수·기간 범위를 먼저 적습니다(4-9, 4-2). 사전에서 비어 있는 칸 중 2절의 확인 항목에 해당하는 것을 한 개씩 묻습니다(두 개까지). 열 정의와 비교 기준이 우선입니다. 비교 기준이 없으면 원인 후보에 순위를 매기지 않고 나열만 합니다(4-10).
2. 계산은 코드 실행으로 처리하고(4-1), 계산식을 결과에 남깁니다. 코드 실행 환경이 없으면 계산 과정을 단계별로 적고 "코드 검증 안 됨"으로 표시합니다.
3. 전체 값과 하위 집단 값을 둘 다 냅니다(4-5). 하위 집단 기준은 표에 있는 열(제품·지역·채널) 중 사용자가 지정한 것, 없으면 행 수가 가장 고르게 나뉘는 열을 씁니다.
4. 비율이 있으면 분모를 표에 명시합니다(4-7). 평균이 있으면 중앙값·범위를 함께 냅니다(4-6).
5. 결과를 사실·해석·원인 가설로 나눠 적습니다(4-10). 원인 후보는 "추정"으로 표시하고, 각 후보를 확인하려면 어떤 데이터가 더 필요한지 적습니다(4-4).
6. 표본 수와 결측·이상치를 결과에 적습니다(4-8). 표본이 작으면 결론의 한계를 함께 씁니다.
7. 6절 형식으로 정리하고 공통 규칙을 적용합니다.

## 6. 출력 형식

형식은 세 가지이며 references/formats/data-formats.md 에 있습니다. 기본은 형식 1(분석 노트)이고, 어느 형식을 쓸지는 그 파일의 "선택 조건"과 references/format-profile.md 5절로 정합니다. 아래는 기본 틀과 채운 예시입니다. 결과 맨 위에 `형식: ○○ — 이유 한 줄`을 씁니다.

```
데이터 개요: 행 ○개, 기간 ○○~○○, 열: ○○ / ○○ / ○○
열 정의(사용자 확인): 매출 = 순매출(반품 제외, 세금 제외)
비교 기준: 전년 동월 (사용자 입력)

[계산 결과] — 코드 실행
| 구분 | 이번 기간 | 비교 기간 | 증감 | 분모(비율일 때) |
|---|---|---|---|---|
| 전체 | ... | ... | ... | ... |
| 하위 집단 A | ... | ... | ... | ... |
계산식: 증감률 = (이번 − 비교) / 비교

[분포] 평균 ○ / 중앙값 ○ / 최솟값 ○ / 최댓값 ○ / 이상치 ○건(행 번호)
[표본·결측] 표본 ○건, 결측 ○건(열 ○○)

[원인 후보 — 추정]
1. ○○ (근거: 하위 집단 A에서만 감소. 확인하려면 ○○ 데이터 필요)
2. ...

[결론의 한계] 표본이 ○건이라 ○○ 집단의 추세는 일반화하기 어렵습니다.
```

원인을 하나로 단정하지 않습니다. 원인 후보와 그 후보를 확인할 방법까지가 이 업무 유형의 결과입니다.

채운 예시 — 데이터 사전(사용자가 실제 값을 주기 전 단계. 값·행 수는 만들지 않고 틀만 채웁니다):

```
| 열 이름 | 뜻 | 단위 | 집계 기준 | 결측 표기 | 확인 |
|---|---|---|---|---|---|
| 월 | 집계 월 | YYYY-MM | 월 단위 | — | 확인됨(표 헤더) |
| 매출 | [확인 필요] 총매출인지 순매출인지 | 원 | 월 합계 | 빈칸 | 사용자 확인 필요 |
| 채널 | 판매 경로(온라인/매장) | 범주 | — | '기타' | 확인됨(값 2종) |
| 반품 | [확인 필요] 매출에서 이미 뺀 값인지 | 원 | 월 합계 | 0 | 사용자 확인 필요 |
```

채운 예시 — 사실·해석·가설 분리(비교 기준 미지정 상태, 예시용 가상 값):

```
[사실] 9월 매출 합계는 8월보다 낮습니다(코드 실행, 행 1~62). 감소는 온라인 채널에서만 나타나고 매장 채널은 8월과 같습니다.
[해석] 전체 감소는 온라인 채널 한 곳의 변화로 설명됩니다. 비교 기준(전년 동월·목표)이 없어 이 감소가 이례적인지는 판단하지 않습니다.
[원인 가설 — 순위 없음] ① 온라인 프로모션 종료(확인하려면 프로모션 일정 필요) ② 온라인 주문 집계 누락(확인하려면 주문 건수 열 필요) ③ 계절 요인(확인하려면 전년 9월 데이터 필요)
```

## 7. 나쁜 질문 → 고친 질문

| 상황 | 나쁜 질문 | 고친 질문 | 적용 기법 |
|---|---|---|---|
| 월별 매출 감소 | 이번 달 매출 왜 줄었어 | 매출 정의(순매출·총매출, 반품 포함 여부)부터 확인하고, 전체가 줄었는지 특정 제품군만 줄었는지 나눠서 보여줘 | 4-2, 4-5 |
| 설문 만족도 | 고객들이 만족한다는 거지 | 만족도 평균 말고 1~5점 응답 분포와 응답자 수, 무응답 비율도 같이 보여줘 | 4-6, 4-8 |
| 광고 성과 | 이 광고 효과 있었네 | 클릭률 상승이 광고 때문인지 같은 기간 다른 프로모션·시즌 요인은 없었는지 확인하고, 분모(노출수) 집계 기준이 두 기간에 같은지도 확인해줘 | 4-4, 4-7 |
| 재고 회전율 | 재고 회전율이 떨어졌으니 문제네 | 계산식이 지난 분석과 동일한지, 평균재고 산정 기간이 같은지 확인하고 계산 과정을 보여줘 | 4-1, 4-2 |
| 근태 통계 | 지각이 늘었다는 거지 | 지각 건수 증가가 인원 증가 때문인지 비율로도 계산하고, 특정 부서에 몰려 있는지 확인해줘 | 4-5, 4-7 |
| 부서별 생산성 | A팀이 B팀보다 생산성이 높네 | 생산성 지표의 정의가 두 팀에 동일하게 적용되었는지, 인원수 차이는 어떻게 보정했는지 확인해줘 | 4-2, 4-7 |
| 웹 트래픽 | 트래픽이 늘었으니 좋은 거네 | 증가분이 신규 방문자인지 재방문자인지 나눠서 보여주고, 봇 트래픽이 섞여 있는지 확인해줘 | 4-5 |
| 신제품 반응 설문 | 다들 좋아한다니까 출시하자 | 응답자가 몇 명이고 기존 고객인지 신규 고객인지 확인하고, 표본이 작다면 그 한계도 같이 말해줘 | 4-8 |
| 설문 결과 첫 해석 | 이 설문 결과 분석해줘 | 먼저 열마다 뜻·단위·결측 표기를 표로 정리하고, 그다음 표에서 읽히는 사실, 해석, 원인 가설을 세 칸으로 나눠서 써줘. 비교 기준은 아직 없으니 순위는 매기지 마 | 4-9, 4-10 |

## 8. 점검 목록

| 실패 | 확인 질문 |
|---|---|
| 분모가 다른 비율을 그대로 비교 | 두 비율의 분모가 같은 기준으로 집계되었는가 |
| 기간이 다른 데이터를 같은 선상에서 비교 | 두 기간의 길이와 시작·종료 시점이 같은가 |
| 평균에 가려진 분포를 놓침 | 평균 외에 중앙값·최댓값·최솟값을 확인했는가 |
| 작은 표본을 전체로 일반화 | 결론의 근거가 된 표본 수는 몇 개이고, 전체를 대표할 만큼 충분한가 |
| 상관을 인과로 단정 | 이 결과를 설명할 다른 요인(교란변수)을 배제했는가 |

## 9. 다음 단계

- 원인 후보가 여러 개면: 후보마다 확인에 필요한 데이터를 요청하거나, 그 데이터가 표에 있으면 후보별로 재계산
- 하위 집단에서 결론이 갈리면: 갈린 집단만 따로 떼어 같은 절차 반복
- 외부 요인(시장·경쟁사·규제)이 후보에 있으면: 자료조사 유형으로 넘겨 그 요인의 사실 여부 확인
- 결과를 보고해야 하면: 기획안 작성 유형으로 넘기되, 원인 후보는 "추정"으로 표시한 채 넘김
