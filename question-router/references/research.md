## 1. 이 업무 유형으로 오는 신호 / 아닌 경우

이 업무 유형은 밖에 있는 사실·사례·수치·문서 내용을 찾아 정리하는 단계입니다. "알아봐 줘", "조사해 줘", "동향이 어때", "사례 찾아 줘", "이 문서 요약해 줘", "이 자료에서 ○○ 찾아 줘"가 신호입니다. 웹 검색이든 첨부 문서든, 결과의 가치가 "어디서 나온 정보인가"에 달려 있다는 점이 핵심입니다.

다음은 겉모습이 비슷해도 다른 업무 유형입니다.

- 데이터 분석: 이미 확보한 수치를 계산·집계·비교하는 작업입니다. 수치의 출처를 찾는 단계는 자료조사, 그 수치로 표나 추세를 만드는 단계는 데이터 분석입니다.
- 결과물 검토: 이미 작성된 문서의 논리·표현을 점검하는 작업입니다. 다만 검토 중 인용된 사실을 원출처와 대조하는 부분은 이 업무 유형의 기법(4-2, 4-3)을 그대로 씁니다.

## 2. 먼저 확인하는 것

| 확인 항목 | 왜 필요한가 | 없을 때 생기는 일 |
|---|---|---|
| 조사 범위(기간·지역·대상) | 범위가 없으면 오래된 정보와 최신 정보가 섞입니다 | 학습 시점 이전 정보를 최신인 것처럼 받게 됩니다 |
| 정보의 출처 제한(첨부 자료만 / 웹 포함) | 첨부 자료만 써야 하는 조사에 일반 지식이 섞이는 것을 막습니다[1] | 문서에 없는 내용이 문서 요약에 들어옵니다 |
| 결과의 용도(보고서 인용 / 내부 참고 / 의사결정) | 용도에 따라 요구할 근거의 수준이 달라집니다 | 인용 불가한 2차 자료가 보고서에 실립니다 |
| 이미 알고 있는 것 | 중복 조사를 줄이고, 반대 근거를 찾는 데 집중할 수 있습니다 | 아는 내용을 다시 확인하는 데 결과가 소모됩니다 |

## 3. 조사 결과를 그대로 믿으면 안 되는 이유

AI에게 조사를 시키면 두 종류의 산출물이 같은 문체로 섞여 나옵니다. 실제 문서나 검색 결과에서 찾은 내용과, 모델이 빈 자리를 그럴듯하게 메운 추정입니다. Anthropic 공식 문서는 모델이 불확실할 때 "모른다"고 답하기보다 답을 만들어내는 경향이 있다고 명시하고, 이를 줄이는 방법으로 "모른다"고 답할 권한 부여, 인용 우선 추출, 주장별 출처 대조, 외부 지식 사용 제한을 제시합니다[1]. Citations 기능은 이 대조를 구조적으로 강제해, 실제 문서에 없는 내용은 인용할 수 없게 만듭니다[2].

확신에 찬 어조도 근거가 되지 못합니다. 모델이 말로 표현하는 확신도는 실제 정확도가 크게 변해도 높게 유지되는 과신 경향이 확인되었습니다[4]. 요약에서는 다른 문제가 생깁니다. 원문의 표본 수·기간·지역·과거형 표현이 빠지면서 "참가자의 75%"가 "사람들은"으로 바뀌는 식으로, 결론이 원문보다 넓게 일반화됩니다[8]. 재무 분석 요약에서는 조건이 빠진 압축본이 실제 투자 판단을 뒤바꾸는 사례가 확인되었습니다[5].

그래서 조사 결과를 받을 때 물어야 할 것은 "그럴듯한가"가 아니라 "어느 문장이 어느 출처의 어느 부분에서 나왔는가"입니다. 이 구분을 요구하는 질문이 없으면 찾은 정보와 지어낸 정보를 가를 방법이 없습니다.

## 4. 질문 전략

### 4-1. "모른다"고 답할 권한 부여

무엇을: 정보가 부족하거나 불확실하면 답을 만들지 말고 그렇게 말하도록 명시합니다.
왜: 모델은 빈 자리를 채우려는 경향이 있고, "모른다"는 경로를 열어 두면 이 경향이 줄어듭니다[1].
질문 문장:
```
제공된 자료로 확인되지 않는 부분은 추측하지 말고 '자료에서 확인 안 됨'이라고 표시해줘.
```

### 4-2. 인용 우선 추출

무엇을: 결론을 쓰기 전에 근거가 되는 원문 문장을 그대로 먼저 뽑게 합니다.
왜: 원문 인용을 먼저 시키면 모델이 실제 텍스트의 표현에 묶여, 문서에 없는 내용을 결론에 섞기 어려워집니다[1][3].
질문 문장:
```
결론을 쓰기 전에 이 보고서에서 관련된 문장을 그대로 인용으로 먼저 뽑아줘. 없으면 '관련 인용 없음'이라고 써줘.
```

### 4-3. 주장별 출처 대조

무엇을: 정리된 내용의 각 항목이 어느 출처의 어느 부분에서 나왔는지 표시하게 합니다.
왜: 문장 단위로 출처를 대응시키면 근거를 찾지 못하는 주장이 드러나고, 그 주장은 제거하거나 따로 표시할 수 있습니다[1][2].
질문 문장:
```
정리한 내용 각 항목마다 근거가 된 원문 인용을 함께 표시해줘. 인용을 못 찾으면 그 항목은 '근거 없음'으로 따로 표시해줘.
```

### 4-4. 외부 지식 사용 제한

무엇을: 제공한 자료 안의 정보만 쓰도록 범위를 좁힙니다.
왜: 범위를 좁히지 않으면 학습 데이터의 일반 지식과 제공 자료의 내용을 구분 없이 섞어 답합니다[1].
질문 문장:
```
아래 첨부한 자료에 나온 내용만 사용해서 답해줘. 자료에 없는 일반 지식은 쓰지 마.
```

### 4-5. 메타인지 재질문

무엇을: 첫 답을 받은 뒤 "이 답이 틀릴 수 있는 지점은 어디인가"를 별도로 묻습니다.
왜: 이 질문을 던지자 모델이 대부분의 실행에서 자신의 편향이나 누락된 반대 증거를 스스로 지적했고, 확신도를 낮췄습니다[6].
질문 문장:
```
방금 답변에서 네가 틀렸을 수 있는 지점, 놓쳤을 수 있는 반대 증거를 짚어줘.
```

### 4-6. 조건 보존 요구

무엇을: 요약할 때 표본 크기·조사 기간·대상 지역·과거형 표현을 그대로 유지하게 합니다.
왜: 요약 과정에서 이 조건들이 빠지며 원문보다 넓은 일반화가 생깁니다[8]. 이 지시는 그 소실 지점을 직접 겨냥합니다.
질문 문장:
```
요약할 때 조사 대상 수, 기간, 지역, '~였다'는 과거형 표현을 그대로 남겨줘. 일반적인 결론처럼 바꾸지 마.
```

### 4-7. 확신도 대신 근거 자료 요구

무엇을: "얼마나 확신하는가"를 숫자로 답하게 하는 대신, 그 판단을 뒷받침하는 자료와 반대되는 자료를 요구합니다.
왜: 모델의 확신도 표현은 실제 정확도와 어긋나는 경우가 많아 신뢰도 지표로 쓰기 어렵습니다[4].
질문 문장:
```
이 판단에 확신도를 숫자로 매기지 말고, 뒷받침하는 자료와 반대되는 자료를 각각 알려줘.
```

### 4-8. 복수 출처 교차 검증

무엇을: 같은 질문을 다른 자료나 다른 실행으로 반복해 결과가 일치하는지 비교합니다.
왜: 서로 다른 실행이나 압축 결과가 상충하는 신호를 내며, 이 불일치 자체가 근거 부족의 신호가 됩니다[1][5].
질문 문장:
```
같은 질문을 이 두 번째 자료로도 확인해서, 첫 번째 결과와 다른 부분이 있으면 알려줘.
```

### 4-9. 학습 지식과 확인 출처 구분 표기

무엇을: 답의 각 항목이 지금 검색·열람한 자료에서 나온 것인지, 모델이 학습한 일반 지식에서 나온 것인지 표시하게 합니다. 학습 지식에서 나온 항목은 "확인 안 됨"으로 둡니다.
왜: 모델은 두 종류를 같은 문체로 섞어 내고, 학습 시점 이전 정보가 최신인 것처럼 전달됩니다[7]. 출처를 열어 확인한 항목과 기억으로 답한 항목을 가르면 어느 항목을 다시 찾아야 하는지 드러납니다[1].
질문 문장:
```
항목마다 '지금 확인한 자료(출처명·URL)'에서 나온 것인지 '네가 알고 있던 내용'인지 구분해서 표시해줘. 알고 있던 내용은 '확인 안 됨'으로 두고 지우지 마.
```

## 5. 실행 순서

1. 2절의 확인 항목 중 빠진 것을 한 개씩 묻습니다(두 개까지). 출처 제한(첨부만 / 웹 포함)은 거의 항상 필요합니다.
2. 조사 범위를 결과 맨 위에 적습니다(기간·지역·대상·출처 제한).
3. 첨부 자료가 있으면 인용 우선 추출(4-2)부터 합니다. 웹 조사면 항목마다 출처명·URL·발행 시점을 붙입니다(4-3).
4. 항목마다 "확인됨 / 추정 / 확인 안 됨"을 표시합니다(4-9). 지금 연 자료에서 나온 것만 확인됨이고, 학습 지식에서 나온 것은 확인 안 됨입니다. 확인 안 됨은 지우지 않고 남깁니다. 무엇이 비어 있는지가 사용자에게 정보입니다.
5. 요약이 포함되면 조건 보존(4-6)을 적용하고, 원문의 조건을 요약 옆에 남깁니다.
6. 결론이 한 방향이면 반대 근거를 한 번 더 찾습니다(4-5, 4-8). 못 찾았으면 "반대 근거 탐색: 없음(탐색 범위 ○○)"으로 적습니다.
7. 6절 형식으로 정리하고 공통 규칙을 적용합니다.
8. 결과를 md 파일로 저장합니다(6절 "md 저장"). 대화창에는 조사 범위 한 줄, 상태 집계(확인됨 ○ · 추정 ○ · 확인 안 됨 ○), 핵심 세 줄, 파일 이름만 씁니다. 표가 대화창에만 있으면 다음 업무 유형에서 다시 쓸 수 없습니다.
9. 추정·확인 안 됨 행이 있으면 다음 질문 제안은 그 행만 다시 조사하고 원문 문장을 인용하게 하는 문장으로 냅니다(9절 1순위). 사용자가 재조사를 요청하면 같은 파일의 근거표 상태를 고치고 "재조사 기록"에 한 줄을 더합니다. 새 파일을 만들지 않습니다.

## 6. 출력 형식

형식은 세 가지이며 references/formats/research-formats.md 에 있습니다. 기본은 형식 1(근거표)이고, 어느 형식을 쓸지는 그 파일의 "선택 조건"과 references/format-profile.md 5절로 정합니다. 아래는 기본 틀과 채운 예시입니다. 결과 맨 위에 `형식: ○○ — 이유 한 줄`을 씁니다.

```
조사 범위: 기간 / 지역 / 대상 / 출처 제한 (사용자 입력)

| 항목 | 내용 | 출처(문서명·위치 또는 URL, 발행 시점) | 상태 |
|---|---|---|---|
| ... | ... | ... | 확인됨 / 추정 / 확인 안 됨 |

원문 조건(요약 시): 표본 ○명, 기간 ○○, 지역 ○○
서로 어긋나는 출처: A는 ○○, B는 ○○ (차이의 원인 추정: ...)
반대 근거 탐색: 있음(○○) / 없음(탐색 범위 ○○)
확인 안 된 항목: ○○, ○○ — 사용자 확인 또는 추가 조사 필요
```

"확인 안 됨" 항목을 빼고 깔끔한 표만 내놓지 않습니다. 빠진 칸이 보여야 사용자가 무엇을 더 찾을지 결정합니다.

채운 예시(사용자 입력: 공식 고객지원 문서만 사용, 용도는 사내 안내문, 주제는 Claude 프로젝트 기능의 파일 업로드 조건):

```
조사 범위: 2026-09 기준 / 한국어·영어 공식 문서 / Claude 프로젝트 기능 / 출처 제한: support.claude.com 문서만

| 항목 | 내용 | 출처(문서명·위치 또는 URL, 발행 시점) | 상태 |
|---|---|---|---|
| 프로젝트당 업로드 용량 | "각 프로젝트의 지식 용량은 ○○" (원문 인용) | support.claude.com 문서 ○○, '프로젝트 지식' 절, 확인 2026-09-15 | 확인됨 |
| 지원 파일 형식 | PDF·텍스트·이미지 (원문 인용) | support.claude.com 문서 ○○, '파일 업로드' 절 | 확인됨 |
| 용량 초과 시 동작 | 오래된 파일이 검색 대상에서 빠진다고 기억함 | 공식 문서에서 해당 문장 못 찾음 | 확인 안 됨 |
| 팀 요금제 공유 범위 | 공유 프로젝트의 파일은 구성원 전체가 열람 | support.claude.com 문서 ○○ | 확인됨 |

원문 조건(요약 시): 해당 없음(수치 요약 없음)
서로 어긋나는 출처: 한국어 문서와 영어 문서의 용량 표기가 다름(차이의 원인 추정: 한국어 문서 갱신 지연)
반대 근거 탐색: 없음(탐색 범위 support.claude.com 내 '프로젝트' 검색 결과 8건)
확인 안 된 항목: 용량 초과 시 동작 — 사용자 확인 또는 추가 조사 필요
```

예시의 수치와 문서 번호는 자리 표시(○○)입니다. 실제 결과에서는 열어 본 문서의 문장을 그대로 넣습니다.

### md 저장

어느 형식이든 결과를 아래 틀의 md 파일로 저장합니다. 파일 이름은 `YYMMDD 주제 리서치.md`, 위치는 사용자의 작업 폴더입니다. 파일을 만들 수 없는 환경이면 같은 내용을 md 코드 블록으로 냅니다.

```
---
주제: ○○
조사일: YYYY-MM-DD
조사 범위: 기간 / 지역 / 대상
출처 제한: 웹 포함 / 첨부만
용도: 보고서 인용 / 내부 참고 / 의사결정
상태 집계: 확인됨 ○ · 추정 ○ · 확인 안 됨 ○
---

## 근거표
| 번호 | 항목 | 내용(원문 인용) | 출처 | 등급 | 상태 |
|---|---|---|---|---|---|
| 1 | | "..." | S1 | A | 확인됨 |

## 출처 목록
| 출처 | 출처명 | URL·문서 위치 | 발행 시점 | 확인일 |
|---|---|---|---|---|
| S1 | | | | |

## 확인 안 된 항목
- ○○ — 다시 찾을 곳: ○○

## 반대 근거 탐색
있음(○○) / 없음(탐색 범위 ○○)

## 재조사 기록
| 회차 | 날짜 | 다시 찾은 항목 | 상태 변화 |
|---|---|---|---|
```

- 출처는 번호(S1, S2)로 따로 모읍니다. 한 출처가 여러 행에 쓰여도 링크는 한 번만 열어 대조합니다.
- 등급: A 공공기관·운영 주체의 공식 발표 / B 언론·업계 자료 / C 개인 글·커뮤니티(참고 수준). 결론은 A·B 행으로만 씁니다.
- 확인일은 출처를 실제로 연 날짜입니다. 확인일이 없는 출처는 확인됨으로 표시하지 않습니다.

## 7. 나쁜 질문 → 고친 질문

| 상황 | 나쁜 질문 | 고친 질문 | 적용 기법 |
|---|---|---|---|
| 경쟁사 동향 | 경쟁사 A의 최근 동향 알려줘 | 경쟁사 A가 최근 6개월간 발표한 신제품을 항목마다 발표 시점과 출처를 붙여 정리해줘. 확인 안 되는 항목은 '확인 안 됨'이라고 써줘 | 4-1, 4-3 |
| 규제 변경 | 이 분야 규제가 어떻게 바뀌었어 | 변경 사항을 시행일과 근거 법령·공고문 원문 문구와 함께 인용해줘. 확실하지 않으면 최신 공식 발표를 확인하라고 알려줘 | 4-2, 4-9 |
| 시장 규모 | 이 시장 규모가 얼마나 돼 | 시장 규모 수치의 출처, 조사 기관, 조사 연도, 추정 방식을 함께 표시해줘. 출처마다 수치가 다르면 그 차이도 알려줘 | 4-3, 4-8 |
| 사내 문서 요약 | 이 문서 요약해줘 | 요약하되 적용 대상, 기간, 금액 기준 같은 조건과 예외는 빠뜨리지 말고 원문 표현 그대로 남겨줘 | 4-4, 4-6 |
| 고객 후기 | 고객들이 뭘 불만족스러워해 | 불만이 반복되는 항목을 뽑되, 항목마다 실제 후기 문장을 인용으로 붙이고 몇 건에서 나온 이야기인지 표시해줘 | 4-2 |
| 해외 사례 | 해외에서는 이런 사례 어떻게 하고 있어 | 국가·기관·시행 연도별로 표로 정리하고, 사례마다 원 출처 링크나 문서명을 적어줘. 오래된 사례와 최근 사례를 구분해줘 | 4-3, 4-9 |
| 업계 통계 인용 | 이 업계 평균 수치 알려줘 | 인용할 거니까 원자료의 정확한 문장과 발행 기관, 발행 연도를 같이 알려줘. 출처를 확인 못 했으면 그렇다고 말해줘 | 4-1, 4-3 |
| 보고서 여러 개 종합 | 이 보고서들을 종합해서 결론 내줘 | 결론이 서로 일치하는 부분과 갈리는 부분을 나눠 정리하고, 한 보고서에만 있는 주장은 따로 표시해줘 | 4-8 |
| 도구 기능 조건 조사 | Claude 프로젝트랑 메모리 기능 차이가 뭐야 | 공식 고객지원 문서만 열어서, 기능마다 역할·사용 조건·제한을 표로 정리하고 항목마다 문서명과 URL을 붙여줘. 문서에서 못 찾은 항목은 '누락·추가 확인 필요'로 따로 모아줘 | 4-4, 4-9 |

## 8. 점검 목록

| 실패 | 확인 질문 |
|---|---|
| 그럴듯한 가짜 통계·가짜 출처 | 이 수치가 나온 원문 문장과 출처 링크(또는 문서명)를 보여줄 수 있는가 |
| 최신성 착오 | 이 정보가 검색으로 확인한 것인지, 학습된 지식에서 나온 것인지 구분했는가(4-9) |
| 요약 시 조건 누락 | 원문의 조사 대상·기간·조건이 요약에도 그대로 남아 있는가 |
| 한 출처 과의존 | 이 결론과 반대되는 자료도 찾아봤는가, 몇 개의 출처를 확인했는가 |
| 확신 어조를 정확도로 오인 | 자신 있게 말한 부분이 문서 근거에 기반한 것인가, 표현 방식일 뿐인가 |
| 결과가 대화창에만 남음 | 근거표와 출처 목록이 md 파일로 저장되어 다음 업무 유형에서 다시 열 수 있는가 |

## 9. 다음 단계

위에서부터 먼저 해당하는 것 하나를 제안합니다.

1. 추정·확인 안 됨 행이 있으면: 그 행만 다시 조사하고 원문 문장을 인용하게 하는 요청. 결과는 같은 md 파일에 반영(5절 9번)
2. 결론이 한 방향뿐이면: 반대 근거를 찾아 나란히 보여 달라는 요청(4-5, 4-8)
3. 수치가 모였으면: 데이터 분석 유형으로 넘겨 계산·비교(단, 출처와 조사 방식이 다른 수치를 한 표에서 비교하지 않도록 조건을 함께 넘김)
4. 조사가 문서의 근거가 되면: 기획안 작성 유형으로 넘기되, md 파일의 확인됨 행만 근거로 쓰고 추정은 추정으로 표시
